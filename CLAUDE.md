# svelte-template

SvelteKit (Svelte 5 runes, TypeScript) + SCSS + JSON content, edited through Decap CMS, hosted on Netlify. Package manager is bun. This is a copy-once template: sites keep what they use and delete the rest, so every feature must be removable by deleting its own files.

## Rules

- **Deletable features.** A component, action or feature owns its JS and CSS. Nothing global may import it by side effect. Removal is: delete the file, delete its imports.
- **Styles.** Component styles live in the component's `<style lang="scss">` with plain class names (Svelte scopes them). Use `@use 'base/mixins';` for mixins. Global SCSS in `src/styles/base/` holds tokens, resets and shared utility classes, and uses BEM (`animate`, `animate--in`).
- **Tokens.** Colors, fonts and spacing are CSS custom properties in `base/_variables.scss`; the light theme is the `light-tokens` mixin. Theme is `data-theme` on `<html>`, set by the inline script in `app.html`.
- **Behavior.** Reusable DOM behavior is an attachment (`{@attach fn(options)}`) in `src/lib/attachments/`, one file per behavior, with typed options. An attachment that needs CSS imports its own SCSS (`import './name.scss'`) so deleting the files removes it completely. Never read `window`, `document` or `innerWidth` at module scope (the module also loads during SSR); read them inside the attachment. Keep files alphabetical; related ones share a prefix (`text-*`). Component-specific behavior stays inside the component.
- **Heavy libraries.** GSAP and its plugins load through dynamic `import()` from one `src/lib/utils/gsap.ts` (`loadGsap('scramble')`); call it from an attachment, never at module scope. The glitch attachments share `utils/scramble.ts` and `attachments/glitch.scss`; the typing attachments share `utils/typing.ts` and `attachments/typing.scss`; the scroll-driven `text-*` attachments (fade, fill, flip, reveal, scale) share `utils/text-scroll.ts` (ScrollTrigger + SplitText, so `scrub`, `markers`, `start`, `end`, `once` and `trigger` work the same everywhere) and `attachments/text-split.scss`. Prefer CSS or `IntersectionObserver` when they are enough. Nothing touches `window` or `document` during SSR; use `onMount` or attachments.
- **Smooth scroll.** Lenis lives only in `components/smooth-scroll.svelte`, mounted once in `routes/(site)/+layout.svelte`. To remove it, delete both and `bun remove lenis`. Add `data-lenis-prevent` to any element that must scroll natively (modals, inner scroll areas).
- **Scroll progress.** `components/scroll-progress.svelte` is mounted once in `routes/(site)/+layout.svelte` and replaces the native scrollbar (it adds a `hide-scrollbar` class to `<html>`). To remove it, delete its import and tag; the scrollbar returns. To keep the bar but show the scrollbar, pass `hideScrollbar={false}`.
- **Mouse cursor.** `components/mouse-cursor.svelte` is mounted once (the `/attachments` page mounts it for demos; add it to `routes/(site)/+layout.svelte` for a site-wide cursor). It reads `utils/cursor.svelte.ts`, which the `cursor-content`, `cursor-hide` and `cursor-target` attachments write to; without the component they do nothing. Looks are `variants` passed to the component, never CSS in the core. `utils/pointer.ts` (shared mouse tracking) and `utils/velocity-tilt.ts` (velocity tilt) are for anything that follows the mouse, including `cursor-field`, which does not need the cursor.
- **Top layer.** `<dialog>`s sit above everything. A component that opens one dispatches `document` event `top-layer-open` so `mouse-cursor` (a manual popover) re-raises itself above it; neither imports the other.
- **Alerts and forms.** `alerts.show({ type, title, message, autoClose })` (`utils/alerts.svelte.ts`) puts an alert on screen from anywhere; `components/alert-stack.svelte`, mounted once in `routes/(site)/+layout.svelte`, stacks them in a column. `components/form.svelte` has two behaviors (`feedback` shows alerts, otherwise it redirects to `/form-submit`). Netlify finds forms only in prerendered HTML, so a page with a form needs `export const prerender = true` in its `+page.ts`. The form is not sent in dev.
- **Page transitions.** A transition is an entry in `utils/page-transition.ts` (keyframes, duration, easing). `components/page-transition.svelte` plays it on real navigations through `onNavigate` and view transitions (mounted once in `routes/(site)/+layout.svelte` with `fade`; change `name`, or delete the import and tag to remove page transitions), and the `/transitions` library frames play the same entry with `playTransition`, so a demo shows exactly what the site would do. Add one by adding an entry, a name in `PageTransitionName` and a demo section.
- **Full-width sections.** `.page-grid` (in `styles/base/_utils.scss`) lays a page out on three columns: children sit in the middle column, limited to `--content-width` with `--body-padding` at the edges, and a child with the class `full` runs edge to edge. It uses grid lines, not `100vw`, so it never adds sideways scroll. The library pages use it; `LibrarySection` is a subgrid of it, so a demo passes `class="full"` (as Marquee and Image Wave do) to break out.
- **Full-screen sections.** Every section takes a `fullScreen` boolean: at least `100dvh` with its content centered, and taller content still grows past it (never a fixed `height`, so long copy on a small screen is not cut off). Heroes default it to `true`; other sections default to `false`. Add it to every new section and document it in `component-props.ts`.
- **Section copy.** Every section that opens with an eyebrow, title, description and buttons uses `components/section-copy.svelte` (hero, carousel, accordion sections and so on), never its own markup. Spacing between those pieces comes only from `--space-eyebrow-title`, `--space-title-paragraph` and `--space-paragraph-cta-group`; use its `layout`, `align` and `show*` props instead of hiding pieces with CSS.
- **Library (documentation pages).** The pages that document the template (`/style-guide`, `/components`, `/attachments`, `/combos`, `/sections`, `/transitions`, `/advanced`) are the library. Every one opens with `HeroSimple`, and every entry uses `src/lib/library/library-section.svelte`: a `[ Title - Type ]` heading (Type is Attachment, Component, Combo, Section, Transition or Tokens). `/advanced` holds heavier canvas and SVG behavior. Small building blocks (button, icon, tag) go in the style guide; larger behavior-owning components (mouse cursor, theme toggle, video overlay) go in `/components`, a brief description, then the options or props as `<ul class="classic-list"><li><code>name</code> description</li></ul>`. Keep entries alphabetical within a page. When you add or change an attachment, component, combo or section, add or update its entry; the prop text lives in `src/lib/library/component-props.ts` (components, sections) or inline on the page (attachments).
- **Deleting the library for a client site.** Everything that exists only for the library is tagged `LIBRARY: DELETE ME` (search for it). Remove: `src/routes/(site)/(library)/`, `src/lib/library/`, `src/lib/utils/nav.ts`, the library links in `src/lib/content/global/navigation.json` (the Resources dropdown) and `footer-simple.json` (Explore), and the library entries in `src/lib/content/meta/pages.json`. Then run `bun run check`, `bun run lint` and `bun run build`.
- **Combos.** A feature that ships in more than one form (a component, an attachment, or both together) is shown on the `/combos` page, one section per feature. "Combo" is a docs category only: the code stays in `components/` and `attachments/`.
- **Following the mouse.** Anything that glides toward the pointer uses `utils/follow.ts` (eased catch-up), `utils/pointer.ts` and `utils/velocity-tilt.ts`. The cursor and `mouse-tooltip` share them.
- **Accessibility and motion.** Every animation respects `prefers-reduced-motion`. Interactive elements are keyboard-operable with visible focus, correct roles and accessible names. Prefer native elements (`details`, `dialog`, `popover`, `button`).
- **Collections (blog, podcasts, books, films).** A collection is a folder of JSON files in `src/lib/content/<name>/`; the file name is the slug and the URL (`/blog/the-file-name`). `utils/collection.ts` loads a folder (drafts hidden, newest first) and renders the Markdown `body`; `src/lib/blog.ts` is the example (one `import.meta.glob` plus the post type). Routes are `routes/(site)/blog/+page` (archive) and `blog/[slug=slug]/+page` (post), both prerendered from `+page.server.ts` so post bodies never reach the browser; the `slug` matcher in `src/params/` 404s odd URLs early. A post passes `seo` from its load data to override `pages.json`. The Decap collection is `blog` in `src/routes/admin/config.json` (`format: json`, `slug: "{{slug}}"`; the file name comes from the title only when first saved, so editing a title never moves a URL). To make another collection, copy `blog.ts`, the content folder, the `blog` route folder, `post-card` and the two `blog-article-*` sections, rename them, change the fields, and add a Decap collection and a header link.
- **Images.** Pictures on the site go through Netlify's Image CDN on Netlify builds (`utils/image.ts`): spread `{...imageProps(src, { sizes })}` on the `<img>` for a `srcset` of resized AVIF or WebP files, and set `sizes` to how wide the picture is actually drawn. It is spread, not a component, so a component's scoped CSS still reaches the `<img>`. Local dev and `vite preview` keep the original files; set `IMAGE_CDN=off` in the Netlify build environment to switch the CDN off (`vite.config.ts` reads it). SVG, GIF and other sites' pictures are left alone. The main picture on a screen also gets `loading="eager"` and `fetchpriority="high"`. Uploads in the admin are capped at 8 MB (`media_library` in `src/routes/admin/config.json`); the CDN serves a small copy, but the original stays in git. Share images (`seo.svelte`) are served as a 1200 by 630 JPEG.
- **Headers.** The header's content (links, buttons, mobile menu footer links, admin login) is one file, `content/global/navigation.json`, shared by every header template; each template has its own style file (`header-simple.json`, `header-island.json`) and takes `HeaderNavProps` (`components/header-types.ts`). `headerTemplate` in `meta/site.json` (`simple`, `island` or `absolute`) picks which one `routes/(site)/+layout.svelte` mounts, so adding a header is a component, a style file, a Decap entry and one more branch there. `components/site-nav.svelte` is the full-screen navigation that the simple header (small screens) and the absolute header (small screens, or every size with its `controls` layout) share. The absolute header's `links` layout puts the links in the middle and a `components/strap.svelte` (a pill with a round cut-out made from the loop's huge box-shadow) of social links in the corner. The island floats over the page without taking room in it, and its navigation is a dropdown that grows from it at every screen size.
- **Content.** Each section reads one JSON file in `src/lib/content/`. Its Decap fields in `src/routes/admin/config.json` must match that file's shape, and its props are typed in the component.
- **Decap previews.** Previews mount the real Svelte components, so there is one copy of the markup. Runtime-only state (classes added by actions) must not hide content in the preview.
- **Dev.** `bun dev`; Vite compiles SCSS, so there is no Sass step. Run `bun run check` and `bun run lint` before finishing.
